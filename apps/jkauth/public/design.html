01IDENTITY

One identity, two faces

jkOS is skeuomorphic, not flat-SaaS. A single attribute — data-mode on <html> — switches between two physical worlds. There are exactly two values, "paper" and "dark"; the mode is controlled explicitly and never from prefers-color-scheme. Corners are sharp by default; chrome is built from CSS hardware, not shadows-on-cards.

data-mode="paper"

Warm kraft-paper office — tan/cream layers, dark ink, brass hardware, film-grain multiply, burnt-sienna default accent. Accents press into the paper.

data-mode="dark"

CRT amber-phosphor terminal — near-black warm grounds, #ffb000 amber, text glow, scanline + vignette veils. Accents emit as halation.

02ACCENT CHAIN

The two-accent chain

Both accents are user-driven and co-equal — a vivid primary and a vivid secondary, never a neutral. Apps supply only a default pair; the live pair is the signed-in user's. From two raw inputs the whole palette derives: paper deepens them toward ink for legibility, dark keeps them raw and adds glow. Never hardcode --accent — let it derive; components read the --color-accent* aliases.

Primary family — tracks --accent

05BUBBLE SYSTEM

The pressed / flat accent system

One rule carries the whole component language: primary is struck / pressed (lit face + bevel on paper, halation in CRT); secondary stays flat, one rung down, never pressed. Use the @jkos/ui React wrappers (<Press>, <Bubble>, <Sub>, <Well>, <Sheet>, <Pill>, <TButton>) — don't recreate them.

08GLOW · HALATION

Phosphor glow & halation

Emissive light is scarce and mode-gated: it only lights up in dark mode — on paper the same accent presses IN instead. Switch Face → Dark to see these come alive. .jk-halo / .jk-glow collapse to nothing on paper, so one class is correct in both faces.

10MOTION

Motion vocabulary

Ambient hardware effects (LED pulse, occasional flicker) are the house idiom — subtle, opacity-only. Entrances land in ~200–400ms. Adjust CRT intensity via the --crt-* tokens, never by baking overlay opacity into a component.

view-enter panel-enter item-in modal-in boot-sweep led-pulse data-flicker check-pop
11FOR A DESIGN PASS

The fence — elevate inside these lines

The invariants a design pass must not cross. Push craft on spacing, hierarchy, composition and atmosphere; keep the token names, the two-mode contract and the derivation chain intact.

  • DOExtend the retro-hardware language — LEDs, screws, vents, tape, 7-seg, screens.
  • DOResolve every colour through the --hub-* / --color-* chain.
  • DOReuse the shared classes & @jkos/ui components; make both faces hold up.
  • DOFade colours with withAlpha(), never hex-concat on a CSS var.
  • DON'TRename any --hub-* token, or hardcode --accent / a hex in a component.
  • DON'TUse prefers-color-scheme — mode is driven by data-mode.
  • DON'TAdd an icon library, or normalise the chrome toward flat modern UI.
  • DON'TRestate the derivation or re-set a CRT knob per app — inputs only.
